사용자가 선택한 가상 팀 업무 사례의 새 지식을 실제 테스트와 함께 작성해 draft GitHub PR을 생성하라. 대상 ../team-agent-knowledge. 스킬 SKILL.md와 저장소 schema, 기존 main 지식을 읽고 따르라. [이전 사례 관련 두 문장은 이 제출용 발췌에서 생략] 사용자 요청은 브랜치 push와 PR 생성을 승인하지만 사용자가 직접 검토·병합하므로 승인/merge와 Hindsight 쓰기는 절대 하지 않는다.

구현 범위는 이해하기 쉬운 가상 Python 설정 검사 예제다. 설정에 필수 `model` 항목이 빠졌을 때, 기존 구현은 막연한 '설정 오류'만 출력하지만 개선된 구현은 '설정 오류: model 항목이 없습니다'라고 구체적으로 알린다. model이 있을 때는 정상 동작한다. 예제는 외부 서비스 없이 실행되며 실제 코드를 보여주고, 변경 전과 후의 입력과 출력 및 테스트로 사실을 검증하라. 범위가 이 예제에 한정됨을 명시한다. 보안상 사용자 제공 값이나 기밀을 오류에 노출하지 않는다. 지식 후보는 사용 가능한 COMP-015 r1을 쓰고, 실제 재현 파일을 별도 커밋 후 그 SHA를 근거로 지식 YAML을 작성한다. 프로젝트 schema, validator를 따르고 근거가 실제로 작동해야 한다.

미래 후속 작업은 또 다른 필수 `version`이 동시에 빠졌을 때 두 항목을 모두 안내하도록 추가 갱신하는 것이다. 이는 사용자의 r1 병합과 수동 게시 후 따로 확인할 계획이므로 이번 PR에서는 이미 구현·게시·관찰했다고 주장하지 마라. r1 지식도 오직 model 누락에 한정하며 version 또는 모든 필수항목을 다룬다고 말하지 마라. 실제 재현, 단위 테스트, 기존 프로젝트 검증, git diff --check를 수행하고, CI를 확인한 뒤 draft PR 링크를 보고하라. 사용자의 환경에는 ../work/hindsight-venv/bin/python Python 3.12 및 의존성이 설치돼 있다. 작업 이력·프롬프트에 과제 원문, 비밀, 개인 경로를 포함하지 마라.
